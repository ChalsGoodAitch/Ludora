1. Instalar los componentes

El tema principal gestiona la presentación. Ludora Booking contiene salas, extras, paquetes, precios, disponibilidad, reservas e integración de pagos. El tema hijo opcional sirve como ejemplo de personalización. El plugin de reservas también puede funcionar con otro tema.

  1. Haz una copia de seguridad de la base de datos y de wp-content. Trabaja primero en un entorno local o de pruebas.
  2. En Apariencia → Temas → Añadir nuevo → Subir tema, selecciona el instalable ludora.zip y actívalo.
  3. Instala y activa voluntariamente el plugin recomendado por el tema, o sube ludora-booking.zip desde Plugins → Añadir nuevo. El archivo completo de documentación y fuentes no se instala como tema.
  4. Si quieres personalizar código, instala ludora-child.zip después del tema principal y activa el hijo. Conserva allí tus cambios.
  5. Para cobrar, instala WooCommerce por separado desde WordPress.org y completa su configuración. Las solicitudes manuales no lo necesitan.

Los mínimos declarados son WordPress7.1.4 y PHP8.4 de64 bits. La base de datos comprobada es MariaDB11.4.8 con InnoDB; configura al menos256MB para WordPress/PHP y HTTPS antes del uso real. Otras combinaciones de base de datos, PHP o WordPress no están verificadas. El comprador no necesita npm, Node, Composer ni Docker en su alojamiento.

2. Configurar el negocio y la demostración

En los ajustes de Ludora, selecciona una zona horaria IANA, por ejemplo Europe/Madrid, información de contacto, correo del negocio, página de condiciones y modo de reserva. Los horarios de sala utilizan esa zona; los intervalos se guardan en UTC. Revisa los minutos de retención para pagar, las horas de espera manual y los días de conservación.

El idioma de WordPress permite utilizar el catálogo español. Los textos originales del código son ingleses. El importador permite elegir una demostración inglesa o española; no traduce automáticamente los textos de tu negocio ya existentes.

Importa la demostración expresamente desde Ludora. Incluye tres salas de ejemplo, extras, paquetes y páginas editables con datos y precios ficticios. Una segunda importación omite sus elementos existentes. Cambiar la portada y el blog requiere marcar la casilla correspondiente. Activar el tema no importa contenido. Sustituye fotos, datos, políticas, precios y descripción de instalaciones antes del uso real.

3. Salas, extras y paquetes

Publica la sala y marca «Disponible para reservar». Los campos guiados guardan las reglas; el editor normal guarda la descripción y las imágenes. Una sala publicada pero desactivada para reservas no puede contratarse. En el editor de WordPress7.1 abre el panel Meta Boxes de la parte inferior para acceder a la configuración guiada; enfoca su botón y pulsa Intro si hace falta. Guarda la entrada después de editar. Este recorrido nativo se comprobó en la prueba de administración con navegador.

El editor valida extremos horarios del mismo día. «Día completo» significa la jornada comercial configurada; no una cesión libre de 24 horas. Los intervalos de apertura separados, los cierres y los márgenes pueden impedir una solicitud.

La configuración JSON avanzada conserva excepciones de apertura, tarifas por fecha y bloqueos técnicos al guardar los campos guiados. Activa la edición avanzada únicamente para reemplazar el objeto completo y guarda antes una copia. Sigue la configuración de demostración y las pruebas de dominio de la versión instalada; no inventes nombres de propiedades.

Extras

Selecciona precio por reserva, hora, asistente o unidad. En asistentes, elige niños, adultos o todos. Introduce importe neto en unidades menores, cantidades mínima y máxima, obligatoriedad, IDs de salas admitidas y modalidades. Capacidad compartida 0 significa ilimitada; un valor positivo limita las unidades simultáneas entre reservas. Los extras obligatorios o incluidos en paquetes se comprueban en el servidor.

Paquetes

Selecciona una sala y modalidad. Para turnos, escribe la clave exacta; para horas, la duración en minutos. Indica las cantidades mínimas de extras publicados que deben incluirse. El paquete compone sala y extras configurados: no acepta un precio arbitrario del navegador ni implementa una señal. Publica los elementos relacionados y comprueba un presupuesto después de cambiar reglas.

4. Montar las páginas y personalizar

Utiliza el editor del sitio para logo, navegación, colores, plantillas y bloques nativos de WordPress. Añade los bloques del plugin para salas, extras, paquetes, datos de empresa y formulario de reserva. La demostración es editable. Las reglas pertenecen al plugin, no a las plantillas del tema. Cambiar de tema no debe eliminar las reservas.

Después de personalizar, revisa móvil y escritorio, teclado, foco visible, títulos, etiquetas y textos alternativos de imágenes. Para idiomas de derecha a izquierda, selecciona una configuración RTL de WordPress e inspecciona dirección y alineación. La compatibilidad de traducción no certifica todos los idiomas ni plugins externos.

5. Disponibilidad y estados

El visitante elige sala, fecha, modalidad, asistentes y extras; revisa el presupuesto calculado en el servidor y facilita los datos del adulto responsable, aceptando tus condiciones. El plugin no recoge perfiles infantiles ni datos de tarjetas. Un cambio de precio o inventario puede exigir recalcular antes de reservar.

Estado técnicoSignificado
holdRetención temporal de capacidad para completar el pago.
pendingSolicitud manual pendiente del local y sujeta a caducidad.
confirmedReserva aceptada. El estado del pago se conserva por separado.
expiredPlazo temporal vencido. La disponibilidad lo ignora incluso antes de la limpieza programada.
cancelled / rejectedReserva cerrada. Cancelar no inventa un reembolso.
completedServicio finalizado; no puede completarse antes de su hora de fin.

Los intervalos son semiabiertos: acabar a las 12:00 permite empezar otra reserva a las 12:00 si los márgenes lo permiten. Se rechazan horas locales inexistentes o ambiguas por el cambio estacional. Las operaciones de inventario y confirmación usan transacciones y bloqueos de recursos en la base de datos.

En administración revisa filtros, fechas, datos, historial y acciones permitidas. Una reserva manual confirmada puede seguir pendiente de pago. Una reserva pagada solo puede cambiar de fecha manteniendo su tratamiento fiscal; para cambiar importe o fiscalidad, gestiona cancelación/reembolso y una nueva reserva. Mantén confidenciales los enlaces privados.

6. Cobro completo con WooCommerce

Activa el modo WooCommerce después de configurar moneda, decimales, impuestos, dirección del local, correo y pasarelas. Los precios del catálogo siempre son netos y enteros en unidades menores, con la precisión activa. Cambiar moneda o decimales reinterpreta los enteros existentes: revisa todas las tarifas. En modo manual se aplica el impuesto configurado en puntos básicos; en WooCommerce manda su configuración fiscal.

El servicio presencial utiliza la clase estándar de impuestos de WooCommerce y la ubicación base del negocio, con código postal y ciudad. Es una decisión fiscal para el local físico, no un cálculo de servicios digitales según domicilio del cliente. Comprueba su adecuación con tu asesor. WooCommerce aporta moneda, precisión, cálculo y redondeo. El presupuesto guarda el tratamiento fiscal. Los cambios de tipos, moneda, cupones, recargos o totales no sustituyen silenciosamente lo aceptado.

El plugin prepara un producto virtual oculto para una reserva en el carrito nativo. Se cobra la totalidad y se admite una reserva por pedido; preparar la reserva reemplaza todos los artículos existentes del carrito, por lo que no debe combinarse con compras de otros productos. La integración utiliza las API oficiales de WooCommerce y Checkout Blocks. Los reintentos de pedidos ya enlazados utilizan la URL oficial de pago. No hay señales, cestas de varias reservas ni formularios propios de tarjetas.

Utiliza WooCommerce11.3.0 con HPOS y Checkout Blocks nativo. Configura por separado la pasarela elegida. Configura tu pasarela y pruébala en su entorno de pruebas antes de publicar. No uses tarjetas reales en la demostración local. Una transferencia pendiente no demuestra recepción de dinero; el local o la pasarela debe marcar el pedido como pagado. Los eventos pagado, fallido, cancelado y reembolsado totalmente pasan por el servicio de dominio. Los duplicados son idempotentes y un fallo tardío no revierte un pago confirmado. Un reembolso parcial no cancela la reserva ni la marca totalmente reembolsada. El reembolso total actualiza el pago; revisa por separado el estado de la reserva.

Si llega un pago tras vencer o cancelar la reserva, se registra y se comprueba de nuevo la capacidad. Si otra reserva la ocupa, no se desplaza: consulta el historial/aviso y acuerda devolución o alternativa. El plugin no promete un reembolso automático del proveedor. WooCommerce conserva sus propios registros y reglas de retención.

7. Copias, actualizaciones y privacidad

  1. Copia juntos base de datos y wp-content, incluyendo tablas de reservas, datos de WooCommerce, imágenes y tema hijo.
  2. Restaura una copia de pruebas y comprueba enlaces privados, pedidos e inventario futuro.
  3. Actualiza tema principal y plugin con la versión revisada. Repite idioma, precios, correo, reserva manual y pago de pruebas.
  4. Conserva el tema hijo. No reemplaces la base de datos real por la demo. Si hay que retroceder, restaura código y base de datos coherentes.

El mantenimiento de WordPress caduca registros temporales y anonimiza reservas cerradas elegibles tras el periodo configurado. Configura cron fiable para las tareas; el bloqueo de disponibilidad caducado no depende de cron. El correo exige un transporte funcional: capturarlo en Mailpit local no demuestra entrega real.

Las herramientas de exportación y borrado de datos personales de WordPress incluyen Ludora. Se pueden retener reservas activas sin resolver y anonimizar registros cerrados elegibles. WooCommerce se gestiona aparte. Revisa aviso de privacidad, obligaciones de conservación, correo y copias antes de publicar.

Desactivar conserva datos. La desinstalación solo elimina datos cuando se ha activado expresamente la opción de purga; revisa uninstall.php y copia antes. Borrar el tema es distinto de borrar el plugin. No actives la purga para cambiar de tema.

8. Resolver problemas y reproducir pruebas

  • Sin disponibilidad: revisa publicación, activación, zona horaria, aforo, apertura, cierres, excepciones, antelación, horizonte, incrementos, márgenes, extras compartidos y reservas retenidas.
  • Precio cambiado: vuelve a calcular tras cambios de tarifas, moneda, precisión o impuestos. El navegador no decide el importe.
  • No se puede pagar: comprueba activación y modo WooCommerce, página nativa de pago, pasarela, vigencia y tratamiento fiscal. Excluye sesiones, REST de reserva y carrito/pago de cachés de página.
  • Estado inesperado: consulta pedido y auditoría juntos. Cancelar no es devolver y una reserva caducada puede recibir un pago tardío.
  • Falta correo: comprueba transporte y bandeja de salida, remitente y dominio con tu alojamiento.
